# یادداشت تصاویر مرجع بازطراحی Hexara

تاریخ ثبت: ۳۰ ژوئیهٔ ۲۰۲۶

این پوشه مرجع بصری و خط مبنای رابط فعلی را نگه می‌دارد. تصاویر مرجع، خروجی نهایی یا مجوزی برای کپی مستقیم از بازی‌های تجاری نیستند؛ فقط برای استخراج زبان بصری، سلسله‌مراتب، میزان جزئیات و کیفیت اجرایی استفاده می‌شوند.

## نقش هر تصویر

| فایل | کاربرد |
|---|---|
| `asset-pack-reference-01.png` | مرجع پوشش کامل خانواده‌های دارایی: زمین، توکن، کارت، بندر، مهره، دکمه، آیکن و پنل معامله |
| `asset-pack-reference-02.png` | مرجع نظم یک شیت دارایی، هم‌خوانی قاب‌ها و مقیاس‌پذیری اجزای بازی |
| `target-ui-concept.png` | مرجع چیدمان بازی، نقشهٔ مرکزی، پنل بازیکنان، معامله، چت و رفتار موبایل |
| `baseline/*.png` | وضعیت واقعی Hexara پیش از هر تغییر، در اندازه‌ها، جهت‌ها و تم‌های مختلف |

## ویژگی‌هایی که باید الگوبرداری شوند

- نقشه باید نقطهٔ تمرکز باشد و نسبت به پنل‌های کمکی عمق و جزئیات بصری بیشتری داشته باشد.
- هر نوع زمین باید از فاصلهٔ معمول بازی بدون اتکا به متن قابل تشخیص باشد.
- عدد، مهره، راه، بندر، نشانگر انتخاب و افکت‌های موقت باید لایه‌هایی مستقل از بافت زمین بمانند.
- کارت‌ها و پنل‌ها باید یک نظام قاب، فاصله، سایه، گوشه و حالت تعاملی مشترک داشته باشند.
- رابط تیره می‌تواند حس ممتاز و سینمایی داشته باشد، اما خوانایی و تم روشن باید هم‌سطح باقی بمانند.
- طراحی باید در RTL و LTR طبیعی باشد؛ صرفاً آینه‌کردن همهٔ اجزا کافی نیست.
- در موبایل، اطلاعات باید در شیت پایین صفحه با حالت‌های بسته، نیمه‌باز و تمام‌صفحه سازمان‌دهی شود تا نقشه همچنان قابل استفاده بماند.

## مرز هویت مستقل

- از نام، لوگو، تصویرسازی، ترکیب‌بندی دقیق، آیکن یا دارایی اختصاصی Catan و محصولات مشابه کپی نمی‌شود.
- پالت، سیلوئت‌ها، بافت‌ها، قاب کارت‌ها و نمادها برای جهان بصری مستقل Hexara طراحی می‌شوند.
- هر دارایی تولیدی باید منشأ و مجوز روشن داشته باشد؛ اولویت با خروجی‌های ساخته‌شده برای همین پروژه و SVGهای کدنویسی‌شده است.
- تصاویر مرجع در محصول نهایی نمایش داده نمی‌شوند.

## قواعد فنی دارایی‌های آینده

- SVG برای آیکن‌ها، نشانگرها، مهره‌های دوبعدی، بندرها و اجزای رابط ترجیح دارد.
- WebP/PNG برای بافت‌های تصویری، فریم‌های تاس یا جلوه‌هایی که با SVG به‌صرفه نیستند استفاده می‌شود.
- برای هر خانواده نام‌گذاری پایدار، نسبت تصویر ثابت، حالت fallback، متن جایگزین و ثبت در رجیستری لازم است.
- دارایی‌های زمین باید تنوع کنترل‌شده و تکرارپذیر داشته باشند؛ انتخاب تنوع باید از داده/seed پیروی کند و چیدمان بازی را تغییر ندهد.
- توکن‌های عدد، مهره‌ها و وضعیت‌های تعاملی نباید داخل تصویر زمین پخته شوند.
